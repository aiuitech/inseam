The official combined correctness/completeness score is **78.98**, with **82 of
100 answers correct**. All 100 questions completed and were judged; none were
skipped or corrected. This is the requested review point. No 500-question extension
or indexing resumption is running.

## What failed

There are 18 incorrect answers: nine basic, three miscellaneous, and six high-level.
Of the twelve incorrect questions with expected documents, eleven have zero
expected-document recall both initially and in the combined agent trace. Missing
the relevant source is the dominant observable failure in that group. This does
not establish whether the cause is lexical mismatch, ranking, or navigation depth.

The exception is `qst_0022`: the expected document was exposed, but the answer used
a different liability cap and exceptions from related material. It fell from 100
to zero. `qst_0014`, about a customer's rollback practice, fell from 33.33 to zero.
`qst_0013` lost ten completeness points. Conversely, the bridge/NAT and null
`max_tokens` answers, `qst_0019` and `qst_0020`, improved from 66.67 to 100.

High-level answers still substitute related material for the requested company-wide
facts. The failures concern the mission, inference-engine design items, routing
policy dimensions, revenue streams, commercial add-ons, and departments. The next
useful diagnosis is source coverage for these questions and wrong-source selection
for `qst_0022`, not an assumption that a larger run will itself improve anything.
No additional algorithm change was made after scoring.

## Runtime and cost

Total active wall time was **634.14 seconds, 10 minutes 34 seconds**. The shared-node
answer batch took 427.18 seconds and judging took 206.47 seconds. The batch reported
**$11.00** in answer-provider charges. Judge charges are not recorded by this harness.
No execution retry was needed.

Eight independent discovery sessions shared one database owner. Per-question times
overlap and must not be summed as wall time. The earlier 50-question run took
18 minutes 44 seconds with sequential answers, but both concurrency and question
mix changed, so that comparison cannot isolate an algorithm speed gain.

There were 368 `find` calls, including the initial searches, comprising 504 searches,
390 scans, 26 expansions, 186 inspections, and 225 forget actions. The twenty
unanswerable questions used 311 searches and 157 scans and account for about half
of cumulative answer-session time. One reached the twelve-turn limit.

## Configuration and limits

- EnterpriseRAG v1.0.0; all 511,962 documents remain in the existing full index.
- First fifty and last fifty release questions, `qst_0001` through `qst_0050` and
  `qst_0451` through `qst_0500`. This is a development sample, not a leaderboard estimate.
- `openai/gpt-5.4` for answers and both official judge roles. Agent effort uses the
  endpoint default; the unchanged upstream judge uses its existing medium effort.
- Upstream evaluator revision `d36685e273713975ee20299bbf1ab64165575b3c`, four judge
  workers, no gold correction, twelve agent turns, and the final answer review.
- Binary source `906fdfe8e1c9`, with an empty Rust source diff. The binary hash and
  source/index provenance are recorded with the run.
- Finder uses 60 seeds, RRF 60, damping 0.5, and lexical weight 0.1. The batch probes
  fifty results and scores the first eight. It does not request score ledgers;
  the inherited manifest `explain` value was corrected to false after execution.
- This evaluates current query code against the earlier full index. The interrupted
  vocabulary slice was not finished, and its enrichment is not measured here.
