# Transforms

A transform takes a fragment of a mimetype it claims and emits child fragments with typed relations ([design/indexing.md](../../design/indexing.md)). Each transform is a **plugin**; the registry they sign up with is the `transforms` seam ([../architecture/kernel.md](../architecture/kernel.md)).

## One registration pathway, two tiers

Linked (Rust) transforms and loaded (WASM) transforms register the same way: `claims(mimetype, is_root)` + `apply(ctx) -> output`, plus a per-run LLM call budget and a **shape fingerprint** (a config digest; the artifact version for loaded ones) that feeds the shape stamp ([maintenance.md](maintenance.md)). Registration returns an undo function held as a fiber effect — unmounting the plugin runs it, and the next sweep notices the difference.

The sweep applies transforms recursively: over the source root, then over every fragment they emit, until nothing claims the output. A transform claiming another's emitted mimetype (the loaded tier's usual shape — e.g. OCR emitting `text/plain` from images) chains in the same rebuild. Every claimant of one fragment is applied at the same time (they are independent of each other), and their outputs are taken in a fixed order — structural transforms before enrichment ones, then by entry id — so budgets and the resulting subtree are deterministic no matter what order plugins started in or which application finished first. Many sources are planned at once too ([maintenance.md](maintenance.md)).

Capabilities are handed in, never grabbed: the context carries the text, optionally the raw bytes (only for transforms that declare `wants_bytes`: the source's at the root, the referenced content's for a fragment with a content reference — below), and optionally a **granted LLM** (`GrantedLlm`) — metered against the transform's per-run budget and checked against the `LlmCall` guard on every call. Budget spent, or guard says no → the LLM handle refuses, and the transform falls back gracefully.

Output is uniform: `sprouts` (child fragments, each with the relation kind from the input to it — a summary is a sprout related `derives`) plus `keyed` sprouts: fragments shared index-wide under a plugin-namespaced key, with an **anchor** rule (the input fragment, or every source-content fragment whose text contains a needle) the sweep resolves, since a transform can't know fragment ids. Relation kinds are an open vocabulary: the kernel defines `contains` and `derives`; a plugin names any other kind it needs (kebab-case) and the finder weights it by name.

## Content references

A fragment normally carries text. A fragment whose content is bytes somewhere else — an image a document links to, a file a message attaches — carries a **content reference** instead: `content_address`, the address of the bytes. The index stores the reference, never the bytes (source data never moves; [design/addressing.md](../../design/addressing.md)), and reads them through the connection stewarding that address's host exactly when they are needed:

- **during planning**, when a byte-wanting transform claims the referenced fragment as a non-root — an OCR transform claiming `image/png` non-roots gets the linked image's bytes just as it gets a root image's. One read per fragment, shared by every claimant of it, bounded by the sweep's `max_content_bytes`; a host that is not mounted, a failed read, or an oversized target withholds the bytes (logged), and the fragment stays a bare reference;
- **on fetch**, when a client asks `fetch_bytes` for the referenced address — the referencing fragment's mimetype is the content type ([../finder/operations.md](../finder/operations.md)).

**The crawl depth.** A follower that emits references to content whose own transforms emit more links — a page follower over `text/html` beside the links transform — would recurse into the web without a bound of its own, so the sweep carries one: `max_reference_hops` (default 1) is how many content references a chain may follow away from a source. Hop 1 is what the source itself links to; hop 2 is what that content links to. Past the cap a reference is still planted — it appears in `expand`, and `fetch_bytes` serves it — but the sweep applies no transform to it and reads no bytes for it, so the chain ends there whatever the follower would have done. The transform context carries `reference_hops_left`, and the links transform skips its probe when it is zero, since a reference that will not be followed is not worth a request. The dial is shape: changing it re-indexes the sources it affects. `0` stores references without ever following one.

The root never carries a reference: its content is the source itself. Linked transforms emit references today (`NewFragment::content_address`; the links transform is the first); the WIT projection does not carry the field yet, so loaded transforms emit text fragments only, but they *claim* referenced fragments like any other and receive their bytes through `source-bytes` — which is what lets the OCR plugin transcribe linked images by claiming non-roots. Mount the [web host](web-host.md) before the sweep that should transcribe them: mounting a connection changes no shape stamp, so a later mount makes existing references fetchable but does not re-run OCR until something else re-indexes the source.

## The first-party transforms

- **Markdown** (structural, `text/markdown` and `text/plain` roots) — splits the document by its own heading outline; sections nest as written and keep the root's mimetype, `http(s)` links become `text/uri-list` children (`links-to`). Documents with no headings fall back to chunking, which is why plain text shares the handler: a `#` heading in a `.txt` file is the same outline, and its absence is the same paragraph chunking.
- **Directory** (structural, `inode/directory` roots) — the handler for folder sources ([folders](#folders)): parses the listing the sweep composed and plants one `text/x-inseam-entry` fragment per child (`contains`), naming the child and its type and referencing its address, so `expand` on a folder walks to what it holds.
- **Chunker** (structural, the other indexable text roots — JSON, CSV, YAML, code) — paragraph-boundary chunks aimed at `target_chars` (hard break at twice that), with line extents.
- **Summarizer** (enrichment, every root) — **mandatory**: every indexed source gets a summary fragment (`text/x-inseam-summary`; the root `derives` it). The summary is written to be found: it answers what someone would be looking for when this source is the right one, in a searcher's words. Four qualities depending on circumstance, and the provenance rides the mimetype as `via=`: **verbatim** when the text already fits `target_chars` (it is its own summary; no call is made), **llm** when the capability is granted, **extractive** when there's text but no LLM, **envelope** when the content was never read. Beside an LLM or extractive summary it plants a **keywords** fragment (`text/x-inseam-keywords`, the root `derives` it): at most `keywords_max` terms that name the source, comma-separated, for the full-text index — the model's when the summary is the model's, the text's own weightiest terms otherwise. A verbatim summary plants none: it left nothing out for keywords to carry, and the BEIR runs show a keyword row beside the whole text buys no recall. Keywords rows never get vectors ([embeddings.md](embeddings.md#which-fragments-get-vectors)). Before an LLM call the text is reduced without a model to the sentences that best represent it — one per section first, then by maximal marginal relevance — within `llm_input_chars`, so a long document is summarized from its whole outline and not its head; the same selection is the extractive summary. A document whose first line is a `#` heading leads both with that title: headings are section labels to the selection, not sentences, and the title is the one line most likely to be what a searcher types.
- **Links** (`transform-links`, structural, `text/uri-list` anywhere — not in the base composition) — the link follower: a link to content in its `follow` list (`image/*` by default) becomes a fragment of that type carrying a **content reference** to the link's web address, related `resolves-to` ([content references](#content-references)). The type comes from the URL's extension first, and from the resource's own headers when the [web host](web-host.md) is mounted and `probe` is on; a link whose type nothing can tell, or that the list excludes, stays a bare link. Without the web host the transform touches no network: references are typed offline and become fetchable once the host is mounted.
- **Entity extractor** (enrichment, every root) — uses the LLM to pull out up to `max_per_source` named entities; each is emitted as a keyed sprout (`entity:<kind>:<name>`) that becomes one `text/x-inseam-entity;kind=…` fragment per index, anchored by `mentions` edges from every fragment whose text contains the name. The whole entity vocabulary is this plugin's.
- **Hints** (enrichment, every root; off unless mounted with a budget) — one LLM call per source that plants what a searcher's question is likely to land on. Under the source: `text/x-inseam-hint;kind=synopsis` (two sentences on what the document is and settles), `kind=cue` (up to `cues_max` questions the document answers, in a colleague's plain words rather than the document's jargon, one per line), and `kind=discriminator` (the facts that tell it apart from near-duplicates: dates, regions, customers, versions, outcomes). Across the index, as keyed sprouts with `mentions` edges: glossary terms (`term:<term>` → `text/x-inseam-term`, the internal word with its plain gloss), exact identifiers (`identifier:<id>` → `text/x-inseam-identifier`: tickets, PR numbers, metric and config names, versions), and entities in the entity extractor's own vocabulary, so two sources that share a codename are one hop apart. Hint fragments rank with summaries (they carry vectors under `vectors = "summaries"`); terms and identifiers are lexical rows. A text past `llm_input_chars` is reduced to its telling sentences first, like the summarizer's.
- **OCR** (`plugins/ocr`, loaded, images at the root or linked) — the reference community-tier transform: reads image text through the granted vision LLM, emitting `text/plain;via=ocr` related `transcribes` ([../plugins/loaded.md](../plugins/loaded.md)). Since 0.2.0 it claims non-roots too, so an image the links transform referenced is transcribed like an image file.

The sweep entry's limits prune every transform's output: a depth cap and a per-source fragment cap.

## Folders

A directory is a source too ([design/indexing.md](../../design/indexing.md), folders): type `inode/directory`, `source_type = "directory"`, no bytes of its own. An optional `summarizer.directory_target_chars` overrides the summary length for folders alone. This lets a whole-document profile keep short folder summaries while the directory transform still plants searchable child names and navigation references. Its content is a **listing** the sweep composes from the catalog once its children have landed — one header line, then one tab-separated line per direct child with the child's name, type, and summary (`(not indexed)` for a child no run has summarized yet), folders first, at most 2,000 entries (`inseam_seams::listing`). That text goes through the transforms like a file's: the summarizer reads it as prose, so a folder's summary is derived from its children's summaries and never from their content, and the directory transform turns it into entry fragments. Entry text is the child's name and type only — a child's summary lives on the child, and repeating it under the folder would rank the folder beside the child on every query.

Each entry also relates `contains` to the child's root fragment — resolved from the entry's address when the folder lands (its children landed first) and re-linked when a child is rebuilt later — so folder membership is an edge the finder's walk can cross, not only a reference `expand` can follow ([vocabulary.md](vocabulary.md), facets). Because a folder's content is composed from landed state, folders index after every file, deepest level first ([maintenance.md](maintenance.md#how-a-run-moves-plan-in-parallel-land-in-order)). A folder's summary is served like any other: a query about what a folder holds ranks the folder as a result, and `expand` on it lists the entries with their `content_address`. `fetch` of a folder serves the host's name listing ([../finder/operations.md](../finder/operations.md)).

## Mimetypes the index defines

| Mimetype | Meaning |
| --- | --- |
| `text/x-inseam-summary;via=<provenance>` | the mandatory summary fragment (`verbatim`, `llm`, `extractive`, or `envelope`) |
| `text/x-inseam-keywords;via=<provenance>` | the terms that name a source, planted beside its summary for full-text search (`llm` or `extractive`) |
| `text/x-inseam-entity;kind=<kind>` | a deduplicated entity (the entity plugin's type; a keyed fragment) |
| `text/uri-list` | a link found inside a fragment |
| `text/x-inseam-entry` | one child of a folder's listing: its name and type as text, its address as a content reference ([folders](#folders)) |

These are inseam's own derived types: no transform may claim them, and the wasm bridge refuses components that try to emit them.

A transform may declare an additional `input_shape` identity for a particular claimed mimetype and root position. The sweep includes that identity only for matching entries in a source's stored inventory, and uses the same identity in transform cache keys. The common registration fingerprint (including the assigned model) remains a dependency. The summarizer uses this for `directory_target_chars`, so changing a folder-only limit preserves file summaries and embeddings.
